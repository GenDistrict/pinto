# PINTO 검증 기록

## 0.1.2

Windows x64에서 타입 검사·빌드, 핵심 로직 11개와 실제 Electron 시나리오 6개를 통과했습니다.

- 네모·동그라미·점·선·자유도형 도구가 각각 표시되고 선택되는지 확인했습니다.
- 동그라미 이동·크기 조절, 선의 끝점 변경 후 복사 좌표가 일치하는지 확인했습니다.
- 다섯 종류를 문서 형식 3으로 저장하고 다시 열었을 때 도형과 지시문이 그대로 유지되는지 확인했습니다.
- 이전 문서 형식과 자유도형 묶기·복원 시나리오도 함께 검증했습니다.

## 0.1.1

Windows x64에서 타입 검사·빌드, 핵심 로직 10개와 실제 Electron 시나리오 5개를 검증했습니다. 자유선 시나리오는 자동 포인터 이동의 테스트 시간 초과를 조정한 후 별도로 재실행해 통과했습니다.

- 자유선의 원본 좌표, 여러 선 묶기, 이동, 확대 후 지시 복사와 재실행 복원.
- 이전 문서 형식 1 읽기 및 자유선을 추가할 때 형식 2로 저장.
- 이전 전체 지시 내용 보존과 새 작업의 전체 지시 입력란 제거.
- 기본 화면의 작업 폴더 연결 제거 및 보관 위치 설정의 보조 메뉴 이동.
- 같은 AI 대화에 지시 붙여넣기와 새 대화에서 원본도 함께 전달하기 안내.
- Windows에서 기존 앱을 다시 실행할 때 전달 인자가 재정렬되는 경우를 보완했습니다. 별도 프로필에서 두 번 실행해 같은 프로세스·정확한 보관 경로·준비 응답을 확인했습니다.

## 0.1.0

2026-10-15, Windows x64에서 Node.js 24.18.0과 Electron 44.7.2를 사용해 검증했습니다. 첫 버전의 소스 설치·편집·전달·개인 수정 보존을 구현했습니다.

| 항목 | 결과 |
| --- | --- |
| TypeScript 검사 | 통과 |
| 핵심 로직 테스트 | 7개 통과 |
| 실제 Electron 시나리오 | 4개 통과 |
| 실행용 빌드 | 통과 |
| Node.js를 PATH에서 제외한 Windows 설치 | 앱 전용 Node.js 다운로드, 체크섬 확인, 패키지 설치, 빌드 통과 |
| 설치한 소스의 독립 실행 | 화면 준비 응답과 소스 수정 안내 반환 확인 |
| Windows 바로가기 | 소스 폴더·바탕 화면 바로가기 생성, 실제 실행 확인 |
| 최초 실행 창 표시 | 정상 종료 후 새 실행에서 windowReady와 windowVisible 확인 |
| 실제 소스 업데이트 | 후보 검사·테스트·빌드 후 적용, 개인 수정 보존 확인 |
| 이전 버전 복원 | 이전 소스와 실행 환경 복원 확인 |

핵심 테스트는 확대·이동·뷰포트 변화에 따른 좌표 정확성, 이미지 경계 처리, 복수 대상 지시문, 손상된 문서 거부, 순서가 있는 저장, 작업 폴더 이동, 업데이트 충돌 보호와 백업 복원을 검증합니다.

Electron 시나리오에서는 다음 동작을 실제 앱으로 확인했습니다.

- 점·사각형 지시, 여러 대상에 같은 지시, 작성 중인 내용과 전체 지시 복사.
- 클립보드 텍스트가 실제 참고 파일 경로와 원본 좌표를 포함하는지 확인.
- TXT 저장, 실행 취소·다시 실행, 한글 조합 Enter, 확대 후 좌표 유지.
- 앱 종료 후 작업 복원, 공백·한글이 있는 파일 경로, 최근 작업 전환.
- 실제 클립보드 이미지 붙여넣기, JPEG 회전 정보, WebP, 파일 드롭, PNG 투명도 보존.
- 텍스트 편집과 캔버스에서 각각 동작하는 실행 취소 단축키.
- 앱 수정 안내에 소스 위치·지침·빌드 명령이 포함되는지 확인.
- 지시 목록을 펼친 뒤 이미지가 작업 영역 안에 다시 맞춰지는지 확인.

설치 검증은 별도 소스 복사본에서 실행했습니다. Node.js가 전역 PATH에 없을 때 공식 런타임을 프로젝트 전용 위치에 준비하고 실행하는 흐름을 확인했습니다. 패키지와 앱 소스의 원본을 보존하며 시스템 Node.js 설정은 변경하지 않았습니다.

업데이트 검증은 설치 복사본에 개인 지침과 추가 파일을 만든 뒤 수행했습니다. 새 후보를 검사·빌드한 후 적용했고, 개인 수정이 유지되는 것을 확인했습니다. 자동 백업에서 이전 소스·빌드·실행 환경을 복원했습니다. 후보의 타입 검사 실패 시에는 기존 설치를 교체하지 않는 동작도 확인했습니다.

macOS 설치 스크립트와 로컬 앱 바로가기 코드, Windows ARM64·Mac Intel·Apple Silicon용 CI 작업은 작성되어 있습니다. 이 Windows 세션에서는 해당 환경의 실제 실행을 검증하지 않았습니다. GitHub Actions 설정은 저장소 게시 후 실행할 수 있으며, 현재 원격 저장소는 연결되어 있지 않습니다.

최소 OS 범위는 채택한 Electron과 Node.js 바이너리의 요구사항을 바탕으로 Windows 10, macOS 13.5 이상으로 설정했습니다. [Node.js 24 플랫폼 범위](https://github.com/nodejs/node/blob/v24.18.0/BUILDING.md)

짧은 지시 세 개를 30초 안에 전달한다는 사용성 목표는 실제 사용자 평가 대상으로 남아 있습니다. 자동화 테스트 소요 시간을 사용자의 작업 시간으로 해석하지 않습니다.

재현 명령은 소스 루트에서 실행합니다.

```sh
npm run check
npm test
npm run build
npm run test:e2e
npm run doctor -- --json
```

Windows의 별도 설치 복사본 검증은 `node scripts/verify-install.mjs`, 해당 복사본의 업데이트·복원 검증은 `node scripts/verify-update.mjs`를 사용합니다. 검증 복사본은 `.test-data/`에 생성되며, 실제 사용자 데이터와 분리되어 있습니다.
