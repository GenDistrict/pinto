# PINTO 수정과 업데이트

PINTO의 소스는 사용자 PC에서 직접 변경할 수 있습니다. 처음 설치할 때 `.pinto/baseline.json`에 원본 파일의 해시를 저장합니다. 다시 설치해도 이 기준을 덮어쓰지 않습니다.

## 개인 수정

AI에 원하는 변경을 요청하세요. 새 세션에는 앱의 **앱 수정 안내 복사** 내용을 전달하면 됩니다. AI는 `AGENTS.md`에서 관련 소스와 검증 명령을 확인할 수 있습니다.

```sh
npm run changes
npm run backup
```

첫 명령은 초기 기준과 달라진 소스를 보여 줍니다. 두 번째 명령은 현재 소스를 `.pinto/backups/<백업 ID>/`에 보관합니다. 사용자 이미지·주석은 소스 백업 대상에 포함되지 않으며 원래 데이터 위치에 유지됩니다.

## 새 버전 적용

1. 새 소스를 현재 설치 폴더와 다른 위치에 내려받습니다.
2. 현재 소스에서 아래 비교 명령을 실행합니다.

```sh
npm run update:plan -- --from '/path/to/new-pinto-source'
```

로컬 수정만 있는 파일은 유지합니다. 새 버전만 변경한 파일은 반영 후보가 됩니다. 같은 파일을 양쪽에서 다르게 변경했다면 충돌로 보고하고 자동 적용하지 않습니다. AI가 내용을 비교해 사용자의 변경을 보존하는 병합안을 별도 소스에서 준비해야 합니다.

충돌이 없으면 PINTO 창을 닫고 적용합니다.

```sh
npm run update:apply -- --from '/path/to/new-pinto-source'
```

도구는 별도 후보 폴더에서 패키지 설치, 타입 검사, 핵심 테스트와 빌드를 먼저 수행합니다. 그동안 현재 실행 버전은 유지됩니다. 검증 후 소스가 다시 바뀌었으면 적용을 중단합니다. 적용 직전에는 현재 소스를 백업하고 기존 빌드·실행 환경도 보관합니다. 교체 도중 실패하면 이전 소스와 실행 환경을 복구합니다.

이후 `node scripts/setup.mjs --no-shortcut`으로 실행 확인과 설치 결과를 갱신합니다. 런타임 경로나 바로가기 구성을 바꿨다면 `--no-shortcut`을 생략해 바로가기도 다시 만듭니다.

## 복원

PINTO를 닫고 백업 ID를 지정합니다. 현재 소스도 안전 사본으로 보관합니다.

```sh
npm run restore -- --backup '<백업 ID>'
```

일반 소스 백업에는 빌드·패키지가 없으므로 복원 후 필요한 패키지를 설치하고 다시 빌드합니다. 업데이트 전 자동 백업에 실행 환경이 포함되어 있으면 함께 복원됩니다. 결과의 `safetyBackup`으로 복원 직전 소스에 다시 접근할 수 있습니다.

## 데이터 위치

- 작업 폴더를 지정한 경우: `<작업 폴더>/.image-notes/<문서 ID>/reference.png`, `annotations.json`.
- 단독 실행: Windows `%APPDATA%/PINTO/`, macOS `~/Library/Application Support/PINTO/` 아래 사용자 데이터.
- 최근 작업 목록: 사용자 데이터 폴더의 `index.json`.
- 작업 폴더를 새로 연결하면 현재 문서의 사본을 해당 폴더에 만듭니다. 이전 사본은 유지됩니다.

소스 폴더를 옮겼다면 설치를 다시 실행해 바로가기의 절대 경로를 갱신합니다. PINTO 제거 시 사용자 이미지·주석의 삭제 여부는 별도로 결정합니다.
