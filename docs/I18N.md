# Internationalization

PINTO supports `en`, `es`, and `ko`. On first launch the main process resolves the system locale, falling back to English. A saved `language.json` in the user data directory takes precedence. `--language` overrides the language for one launch. The footer selector persists a choice atomically and updates both renderer text and native menus.

Messages live in `src/core/locales/{en,es,ko}.json`. `src/core/i18n.mjs` is shared by the Electron main process, renderer, core formatting, and Node installation/maintenance scripts. IDs are stable; Korean source messages are retained in the Korean catalog. Interpolation uses named placeholders and never evaluates translated text as code.

User notes, file names, paths, and coordinates are data: changing languages must never translate or mutate them. Image pixels are unchanged. English and Spanish examples use separate localized sample assets. Instruction copy/export uses the selected app language while preserving all user-authored content.

Tests check catalog parity, placeholders, locale normalization, unchanged document data, UI switching, clipboard output, native dialogs/menus/errors, narrow layouts, and preference persistence after restarting. Existing editing scenarios run explicitly in Korean so the test host's language does not affect them.

Run `npm run check`, `npm test`, and `npm run test:e2e`. To produce the real-language example recordings, run `node scripts/record-localized-demo.mjs`. It uses isolated app data and never edits a user's current document. It produces English and Spanish screenshots, recordings, and instruction samples under `docs/examples/`.

Windows is tested locally. macOS remains subject to CI/device verification; a Windows pass is not a macOS pass. Historical product/brand planning documents may remain in Korean and are not the installation guide.
